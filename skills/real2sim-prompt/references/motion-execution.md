# 第二步：从静态场景到动作与原生物理

第一步首帧已接受、需要恢复视频动作或进入 MuJoCo 时读取。仅解释下一步或整理 skill 时不自动启动重建、训练、完整物理或视频渲染。

## 1. 接收已接受的静态场景

读取 robot/human 输入类型、目标机器人/各臂角色、接受记录、工程/配置哈希、源 RGB 与索引、机器人描述、相机/手眼和交互实例。区分“有静态场景”“有运动目标”“有原生 rollout”；首帧成功只完成第一项。保持已接受的核心背景与可信尺度，不重新推理 Pi3 或重建背景。用户暂不考虑时间同步时沿用已记录的帧对应假设。

## 2. 发现真实交互事件

先浏览真实视频，发现物体之间接触、抓持、支撑、包含的建立/解除/改变，为每个事件保留 before / onset（或区间）/ after。仓库参考帧、均匀抽帧仅补上下文，细则见 [事件与复核](events-and-review.md)。

## 3. 恢复运动参考与动作重定向

先按 [robot/human 输入分支](input-and-retargeting.md)选择同硬件状态复用、robot-to-robot 或 human-to-robot。human 输入在本环节把手/指尖与对象相对参考转换为目标机器人的 TCP、方向、开合及关节目标；不是把人体关节角直接拷给机械臂。保留源参考与机器人适配轨迹两套记录。human 目标硬件按[选型与适配](target-robot-selection.md)落实：平行夹爪转换实际开口/传动命令，灵巧手拟合接触面与指关节；换机器人后重新计算 IK、开合与控制，不能沿用另一硬件的关节值。

沿用首帧全局实例 ID，在各视角跟踪真实可见 mask/关键点；SAM 视频传播提供二维轨迹，跨相机/跨时间身份由共享几何与可见性联合核对，遮挡处保留不确定性。用多视角投影恢复目标物、末端的连续位姿和夹爪开合。有关节实测时优先使用并核对 FK；仅 RGB 时固定真实关节链与可信尺寸，以 IK/轨迹拟合估计关节目标，源视频确为机器腕相机时才由机械链与固定手眼共同运动；人体相机保持独立源轨迹，不自动绑到目标机器腕上。

输出源帧映射、真实事件表、物体/末端/关节及开合的参考序列、来源和置信度。优化的 3D 自建目标到达误差不能代替真实 RGB 对齐；保留未参与拟合的可用帧。

人形目标按[人形候选规则](humanoid-retargeting.md)先测试原位置＋原轨迹/接触；未通过时同等覆盖A（原位置＋新接触/轨迹）和B（小幅新位置＋原接触/轨迹），记录各分支实际偏差和证据。

## 4. 动作对齐与五问复核

用 Blender 低成本预览检查真实事件代表关键帧的所有视角，每个关键帧完整回答五问：最大差异、相机对齐、相对位置、穿模/接触、逼真度。相机/目标/夹爪位置先对，再看控制和摩擦。仅在关键帧发现问题或调整后，向前后扩查受影响项至稳定边界；邻域不计入常规关键帧五问分母，首尾 context 单列；相机或手眼改动使相关投影失效，局部轨迹改动不使无关背景失效。

运动学轨迹是控制参考或诊断，不是物体已被物理抓住。目标物的实测/拟合位姿可用于比较，不能在原生任务中逐帧强制设置其状态来冒充接触成功。无需先渲染整段精细视频才开始短物理诊断。

## 5. 构建 MuJoCo 物理场景

按 [迁移与接触校准](mujoco.md)导出 URDF/XML 结构、初态、目标和碰撞几何，容器保留可碰撞空腔。记录质量、惯量、摩擦、驱动限制及来源。第一步已接受的核心背景须同步导入 MuJoCo 作为静态显示网格，保留完整物体、共享坐标和主要布局。显示网格默认关闭碰撞并不贡献质量；碰撞代理独立设置，仅为支撑、可达域和任务路径中必要部分配置简化碰撞体，不能移除真实会接触的实体。复杂 Blender 材质可降级或烘焙后迁移，明确未保留的纹理和着色特性，不能因节省碰撞计算而省略核心背景显示。

## 6. 分阶段执行与校准

多硬件/灵巧手接触与释放校准按[接触面与释放排查](contact-and-delivery.md)检查实际指垫、法向、非抓持手指及完整物体的放置间隙。

先静置/支撑，再接近 → 首触 → 闭合 → 持续双侧承载 → 搬运/任务动作 → 释放/落定。抓取失败依次检查 **对准位置和角度 → 实际闭合量 → 双侧接触及滑移 → 力、力矩、摩擦**。灵巧手检查真实指垫碰撞面及非抓持手指避让，双臂检查待机姿态和臂间碰撞；落定后检查松指是否再次拖动或抛起目标。采用合适的关节/末端控制，Mink 只是 IK 选项。目标由重力和接触推进；辅助约束、附着和状态回放必须单列，不能称为原生成功。

优先减少非预期断触，结合持续时间、冲击/滑移与前后阶段检查原因并修正；任务完成不能代替接触稳定性验收。

推、拉等持续接触动作先校准接触部位/面积、接触法向和施力方向，再调整接近速度、柔顺性与力限。检查非预期滑脱、接触中断、反复冲击、目标抖动及撤离时被拖回，并关联原生力和运动证据；允许任务所需的平稳滑动。阈值结合对象、控制频率和噪声设定并记录，不能用统一阈值、单一力峰值或任务终态代替接触稳定性判断。问题反馈到第4环节的接触复核及前后邻域，局部不稳定先修接触与控制，不据此推断整项任务无法完成。

## 7. 完整回归验收

独立记录导入/FK、基础接触、持续接触稳定性、物理任务成功、穿入/数值稳定及同源视觉对齐。最终磁盘模型/初态/控制做完整相关回归；再将原生机器人、目标和物料状态回传原 Blender 显示场景，保留材质与核心背景。腕部相机跟随原生机械链。

最终在通过安全、接触和任务检查的候选中，比较完整动作的连贯性与稳定性：接近到首触、任务动作到释放及撤离的衔接，速度/加速度突变、无效停顿/反复试探，非预期断触/冲击/滑移和姿态余量；同时报告位置与轨迹偏差。不能以更接近原站位或单一接触覆盖率压过更连贯稳定的整体方案。

## 8. 回传 Blender、优化外观并输出

第 8 环节覆盖前景机器人/工具/交互物体、支撑物和全部已选核心背景，逐对象记录外观处理与复核。按[前后景纹理适配闭环](rendering.md)选择 Poly Haven 等 PBR 素材，必要时结合真实图像生成适配，并验证来源、UV、材质和多视角一致性。

第 8 环节在原生轨迹回传后完成五项外观优化：固定几何和相机 → 调材质 → 补纹理 → 调灯光 → 多视角预览复核，再提高最终采样并输出。外观修改通常只重渲染与视觉检查，不重跑物理；改变几何/动作才重新做相关回归。

人形任务请求视频时，同时保留实际物理速度视频，不能仅用事件压缩对照判断动作稳定性。

第 8 环节默认输出 Real RGB / Blender RGB / MuJoCo RGB 三方同帧对照。只要关键帧就交付事件代表帧及单列的首尾状态；用户要视频再导出全部可用视角的三类逐帧对应视频，实际解码检查帧数和索引。两种模拟渲染使用同一次原生状态序列、匹配的相机投影和时间映射，不能独立挑帧；缺少原生轨迹时标明 MuJoCo 未完成，不能用运动学预览冒充。静态阶段接受的近似不自动否决动作；若运动显露未知区域或进入其接触范围，才重新打开该问题。

省成本的执行顺序：缓存静态阶段 → 一次真实事件/轨迹提取 → 少量局部运动预览 → 无渲染短物理诊断 → 合格候选完整回归 → 一次最终渲染。失败窗口按需展开，不每轮扫描大日志、重写全文五问或渲染整片。
