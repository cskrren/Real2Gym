# 精简状态、批处理与子任务协作（v5.3）

本规范减少重复上下文和工具往返；已有的事件覆盖、五问、接触与最终原生回归门槛保持有效。缓存命中多本身不是错误；优化重复携带的上下文和不必要调用，不为降低命中率清除有用缓存。运行范围和质量由用户请求及验收标准决定。

## 1. 用精简状态接续工作

在结果目录维护一个 `run_state.json`，记录：`run_id`、`fresh_start/rebuild_scene/resume`、技能版本、输入允许清单及内容哈希、范围/接受等级、当前阶段与候选、实际累计轮次、已通过检查及绑定哈希、未关闭问题、下一步、子任务及产物索引。恢复前核对本轮身份及允许输入；fresh_start 新建状态，不接续旧场景状态。详细轨迹、逐帧五问、日志与失败基线分别落盘，状态只引用路径、哈希和必要指标，不复制全文。

阶段切换、候选决策、依赖改变及交接时更新状态；不因工具每返回一行就重写或重读。主入口同一上下文只读一次，参考按当前阶段加载；上下文压缩后先恢复状态和必要规范，确实缺失时才重读相关段落。压缩不丢失用户约束、未解决问题、检查分母或失败证据，不把旧摘要当当前候选的新验收。

## 2. 脚本处理确定性批次

标定拟合、FK/碰撞扫描、短接触诊断、统计、拼图和表格生成尽量放入可复用脚本。可独立的只读检查或无冲突作业并行；有先后依赖、共享写入或设备冲突时顺序执行。先检查运行时、输入和输出契约，不默认场景专用脚本可跨场景复用。

每批写明待检验假设、有限候选列表、扫描区间、判据和输出路径。按主入口的轮次定义计数：每个实际验证的不同修正候选分别累计，回执绑定候选 ID、轮次与结果；未执行列表项不计数，同一未修改候选复验或基础设施重试不另算修正轮，但保留执行记录。批次不能包装无界搜索，下一批根据上一批证据决定。需要看新图、改变物理假设或过阶段门槛时交回主任务判断，不把需人工视觉判断的五问改成脚本自动 pass。短诊断通过后仍对最终磁盘配置做完整相关回归。

## 3. 默认采用最小上下文的子任务

适合并行的例子包括：同一允许输入的视频事件标注、官方硬件资产核验、首帧实例分割、对冻结候选的独立证据审计。先确认任务独立、资源可用且主任务有可并行推进的工作；不为增加代理数拆分几步即可完成的小事，也不让两个代理同时调整同一相机或控制配置。

每个子任务用下面的短交接契约，默认 `fork_turns="none"`（工具支持时），不要传整个父对话：

- **目标与完成判据**：一个有边界的交付，以及必须验证的事实。
- **输入与约束**：允许读取的绝对路径、必要来源/坐标/版本、用户限制、相关技能段落；fresh_start 不读旧场景及旧拟合结果。
- **写入所有权与资源**：独占输出目录或明确只读，设备/服务分配；不得修改其他代理的产物。
- **返回内容**：结论、关键数值及实际分母、未通过项、产物/日志路径与哈希；有实际 usage 回执则附路径。

默认让子任务读必要参考片段而非全套技能与历史日志。主任务不重复做已由子任务完成且证据有效的工作，但必须读回产物并核对当前候选、版本与验收条件；子任务一句“完成”不能作为通过证据。一次创建有用子任务后使用完成通知或有界等待，避免频繁轮询。完成即让其结束活动轮次，工具支持关闭时关闭；不为了确认收到而唤醒。只有新的具体工作才发送后续任务；旧上下文已膨胀或目标不相关时使用新的精简交接。具备有用子任务时采用内部协作工具；缺少该能力则串行完成并记录，不假称并行。

## 4. 工具只返回决策所需信息

完整 JSON、轨迹、图像集与日志写入文件。默认返回退出状态、产物路径、检查分母、极值、失败区间、候选差异和少量错误片段；首次诊断后仅返回变化项。先看总览拼图，再放大有歧义的局部；必要的真实事件关键帧和受影响邻域仍须实际检查。摘要不足以判定时定向读取原始证据，不能仅因输出短就省略失败。

限制搜索路径和命中范围，优先 `rg`；避免反复输出全篇技能、全部历史候选和整段日志。运行状态未变时延长等待，不用大量“仍在运行”回合维持监控。用户要求 token 统计时保存主任务与子任务的实际 usage 回执并分别汇总；缓存输入是输入的子集，不重复相加。累计快照取差值或最后累计值，不把多次快照直接求和；缺失统计标为不可得，不以文本长度或缓存命中率代替实际额度账单。
