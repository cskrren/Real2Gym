# 人形机器人重定向与验收（v4）

仅目标为人形机器人时读取；human-to-robot 和 robot-to-robot 共用。沿用两步八环节、首帧几何、真实事件和五问，不重新发明第三套流程。硬件按[选型与兼容](target-robot-selection.md#宇树人形与末端选项)核对。

## 第一步：目标硬件、原站位与初态

- 记录准确机型、手、官方资产版本/哈希、安装/TCP、驱动限制；H1 与 H1-2 分开，自带五指手不改名为 Dex5-1。资产可导入、官方兼容、安装可信度和任务通过是不同状态。
- 以真实输入中的人体/原机器人位置建立 `source_station`，记录估计来源与不确定性；同时保留目标 `initial_station`。此前可用机器人的偏移站位不自动成为“原位置”。站位包含坐标系、平移和朝向；相机、操作物体与硬件真实尺寸不随可达性调整。
- 单视角 MoGe-3 / 多视角 Pi3X 初始化规则不变：首帧 RGB 主导、仅首帧点云辅助、最多10个后续稀疏 RGB 时间索引补全实体。人体相机保持源轨迹，不绑到替代机器腕部。
- 检查全链，包括待机臂、手指、腰、髋、腿及桌面/背景障碍。区分固定骨盆或支架、重力补偿和自由站立。初始站位移置不是动态步行；执行中移动需连续控制、足地接触和平衡证据，不瞬移基座。

## 第二步第3–4环节：保真目标同等优先

**首先尝试复现 real 视频中的 action，保持原轨迹、原接触点和原位置，确保在避免危险及高难动作、避免不稳定接触动作的前提下完成任务。如果无法执行，再保持原执行逻辑、尽量保持原位置，并继续避免危险及高难动作、避免不稳定接触动作。** 两级顺序不能倒置；不能因为已有替代方案方便而跳过首选验证。比较任务相关轨迹，不要求照搬人体关节角；RGB 推定三维参考不等于实测轨迹。

原方案未通过，记录具体证据；同一轮比较覆盖两个互补分支，不设默认先后偏好：

| 分支 | 站位 | 轨迹与接触 | 要求 |
| --- | --- | --- | --- |
| 首选 | 原位置 | 原轨迹、原接触点 | 首先验证，无法执行后才进入A/B，保存具体失败依据 |
| A | 保持原站位 | 调整接触区域、抓姿或路径 | 标明实际偏差，不能把“操作逻辑相同”写成“原轨迹相同” |
| B | 左右/前后最小必要位移，可组合 | 尽量保留原物体相对轨迹及接触区域 | 记录方向、距离、朝向变化；接近路径若也改变须披露 |
| C | 位置与轨迹均调整 | 保持原执行逻辑 | A/B不足时再考虑，不把历史C误报成A |

“同时”是候选覆盖要求，不要求并行工具、额外代理或无限穷举。选取能检验假设的小幅候选；用户固定站位等硬约束使B不可执行时明确记录。原位置和原轨迹同等重要，分别报告位移与轨迹/接触偏差，不用未说明的权重混合米、角度和像素。

局部 IK 误差只说明对自建目标的拟合；静态可达仍可能接触失败。局部求解失败或若干候选失败不证明硬件普遍不可行。先排查安装、接触面、碰撞与姿态分支，再决定下一次修改。按第4环节复核实际事件关键帧的五问，修改后按需扩查邻域；已接受且未失效的背景/外观不重开。

## 第6环节：稳定执行，优先减少断触

优先减少非预期断触，检查接触建立、维持及撤离是否稳定。断触出现后定位原因、持续时间和前后影响，优先调整接触位置/法向、姿态、进场和跟随控制；检查反复撞击、目标失控、掉落、明显滑脱或无法撤离。接触不稳定与姿态危险分别判断，但两者都应进入候选复核。任务通过不能代替接触稳定性验收，也不豁免真实穿入、关节违规或改变操作逻辑。

- 先校正作用部位、法向、方向与非作用手指避让，再调速度、柔顺性、力/力矩和摩擦。门/抽屉等看接触引起的运动是否符合预期；有力并不等于有效推动。面法向统计可包含边框/把手，不能据此宣称全部接触面板中央。
- IK 关键姿态之间检查连续性；多起点求解可能跳到另一关节分支。可用邻帧姿态正则、步进限幅或连续参考引导，不能只看每帧TCP误差。首次接触到控制切换和释放/撤离要平滑；控制参数来自对象及硬件，不复制案例常数。
- 接触记录包含区间、采样间隔/实际分母、最长断触、力与运动、撤离后状态。控制目标力不等于实际接触峰值；区分单点/合力和采样峰值/全步峰值。采样没有发现异常不等于严格连续保证。
- 短段诊断可从检查点开始，但必须标明范围和恢复方式；拼接成功片段不算完整任务。有效候选从最终模型与初态完整执行，无物体状态重置、抓持焊接或隐式目标驱动来制造成功。

## 第7环节：按完整动作选择

先检查原逻辑、任务结果、碰撞、姿态及本轮要求，再联合比较阶段衔接、速度/加速度变化、停顿/重试、接触建立/维持/解除、冲击/滑移和最终撤离。允许任务所需的平稳滑动；非预期断触优先修正，并复核前后稳定边界。质量相近时选整体改动较小者；不只按接触比例、站位最近或单帧姿态排序。

通过完整回归的替代方案记为 `success_adapted_trajectory`，列出站位、接触、路径和时长的实际改变。固定骨盆、重力补偿、辅助支撑及未验证的平衡分别披露。已有用户接受的姿态与逻辑不被局部控制问题自动推翻，也不以自设关节范围百分比或单一姿态阈值冒充厂商安全标准。

仍有可执行修正时继续处理；仅在用户停止/缩小范围或有具体阻塞时反馈“本轮未完成”，说明验证范围、失败证据与缺项。若满足任务必须违反原逻辑或安全约束，明确不能在这些约束下完成，不能用局部失败宣称数学上的不可能。

## 第8环节：回传、外观与视频

回传同一次原生轨迹到已接受 Blender 显示场景，保留核心背景与源相机。按原流程完成前后景材质、纹理和灯光复核；已有接受的外观可复用。关键帧输出 Real / Blender / MuJoCo RGB。请求视频时额外提供未做事件压缩的原生实际速度视频，用于判断连贯性；三方事件对齐视频单独标注时间映射和替代轨迹。

编码后完整解码并检查帧数、尺寸、时长与关键帧身份；视频、五问、任务摘要指向同一最终候选。记录格式见[输出约定](output-contract.md#人形候选与接受记录)。

## 节省时间与 tokens

共用静态背景、相机、真实事件与硬件资产。每轮只返回实际参数变化、失败区间、接触对和少量图；先用短物理诊断排除候选，合格后一次完整回归与视频渲染。五问按依赖增量更新，不重新解释不变背景。比较实际生效的配置/控制哈希，替换未生效或完全相同的运行不算不同方案；重跑时核对真正控制入口与脚本路径。案例专用优化器不作为未经验证的通用程序发布。
