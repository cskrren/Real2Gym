# 第三步：分层增强与缩幅重试（v5）

仅在用户要求增强场景时读取。前置输入是已接受的场景、目标硬件、动作逻辑及可复验的原生轨迹；未通过的基线先明确状态。复用第一、二步的坐标、机器人结构、接触验收和外观流程，不重建真实输入。

## 1. 先定义任务参与对象与允许修改项

区分被操作对象、交互设施、支撑体、背景/干扰物、机器人安装基准。杯子与微波炉只是本轮示例，替换为当前任务实例后再定义参数与约束。

| 机械项 | 范围与联动 |
| --- | --- |
| 物体几何 | 包括操作对象和交互设施；更新空腔、壁厚、门铰链、抓点、开合量、惯量和显示/碰撞几何；形状或尺寸变化后检查能否抓住、容纳、释放和关门 |
| 物体位置 | 同时支持对象和设施；在支撑平面与对象局部坐标下修改，重建目标和进出路径 |
| 物体朝向 | 同时支持对象和设施；当前默认杯子保持直立，仅绕支撑法线旋转；旋转设施后在其局部坐标核对包含和碰撞 |
| 桌面高度 | 桌面、其上物体和桌面安装机械臂同步变换；支架/桌腿合理衔接地面；地面安装人形通常不随桌上移，按人形规则适配动作 |

本轮默认不独立增强桌面长宽或桌角切角，不随机改变门初态，不替换物体类别、不将杯子翻倒/横放；这些属于未纳入的扩展，不是已验证能力。若用户另行要求，重新定义初态、任务约束和动作阶段。相机、成像与物理属性不自动加入随机项；几何改变引起的合理物理参数更新须记录。

桌面尺寸是承载约束的派生量：根据支撑面、物体足迹与合理边距检查悬空/越界，必要时在本场景合理尺寸范围内调整；不得无限扩大桌面凑通过。开启的门不要求全部投影都落在桌面上，但要检查扫掠碰撞。安装关系由模型和实际硬件决定，不按“机械臂”名称一律绑定桌面；移动支撑面不等于移动地面坐标系。

## 2. 单项测试只给采样参考范围

先登记参数、单位、原值、方向、拟探测幅度和本轮验收条件。每次只改变一个独立参数，调整相应 action，再用最终配置完整执行；短段可筛选失败，但局部通过不能作为整体通过。

由近到远探测，必要时在已测成功/失败之间细化。报告成功值、相邻失败值、失败类型及测试上限；上限内没找到失败就如实记录。它们是特定模型、控制器和容差下的经验结果，不是全局极限、连续可行区间或单调性证明。初态穿入、可达性、抓持、释放、关门、末态稳定性等分别记录；任务已做完但稳定性失败不能写成完全不可达。

## 3. 随机选 1–3 项，失败保持同组合缩幅

- N 可以是单项或多项修改；每个候选随机选1–3项，不要求全部类别参与，也没有跨类别覆盖配额。记录具体对象/参数；两个位置轴可以属于同一类。采样边界是参考，组合后仍须验证。
- 登记随机种子、目标 N、最大候选预算、单候选缩幅预算和幅度策略；N/M由任务规模决定，不固定为本次3/2。可复用未失效的已通过候选，标明来源，按实际参数去重。
- 初次组合失败后，先按失败原因排除实现错误；对超出可行范围的候选，保留所选对象和修改项，略微缩小偏差，再生成初态与动作并验证。例：`p_next = p_base + alpha * (p_current - p_base)`，`0 < alpha < 1`；尺寸比例的基准为1，位置/角度用原场景值或原局部变换。角度按合理旋转插值处理，不直接将绝对世界坐标乘系数。
- 本次试跑用了每轮偏差乘0.85、最多5次缩幅；这是可配置的采样预算，不是通用参数或第一、二步的修正上限。不要修改碰撞/接触/任务阈值来使候选通过。缩幅后仍可能出现新的失败，必须重验。
- 每次保留原始抽样、实际参数、缩幅系数、动作适配差异、模型/控制版本与结果。预算耗尽或变化已不再满足本轮增强目标时，保留失败，换候选或报告 N 不足，不无限逼近原场景凑数量。实现错误单独修复，不与机械不可行混为一谈。

几何/布局修改后，依据对象局部抓点、容器入口与门的接触区域调整动作，不只平移整条关节轨迹。人形继续遵守[首选源动作与替代分支](humanoid-retargeting.md)，不因增强取消连贯性、危险/高难动作及接触稳定性约束。按[原生执行](mujoco.md)验收，不用状态写回、附着、隐藏碰撞或动画代替任务成功。

## 4. 通过后再加外观层：(1+N) × (1+M)

第一层的1是原机械场景，N是已原生通过且不同的机械候选；第二层的1保留各自原外观，M是外观/环境干扰候选。原场景也获得M个变体。公式描述计划候选数；实际生成、原生通过、渲染完成和有效场景数分别统计，不承诺乘积全部通过。

- **材质与纹理**：前景、支撑体和背景一起处理；改变材质类别、图案、贴纸、污渍、划痕等，磨损归入纹理。复用合法来源PBR资产，按需结合生成能力适配；遵循[纹理与打光](rendering.md)，保持尺度、UV和方向一致。
- **真实干扰物**：使用完整日用品资产，例如餐具、食品包装、瓶罐、抹布；合理尺度、支撑与遮挡，保留必要碰撞。不用简单块体替代要求写实的资产。
- **完整背景替换**：优先合适的高质量 Blender 环境，以已接受操作区为锚点衔接尺度、摆放、材质和灯光；记录来源、许可及依赖。完整背景替换同时增强前景纹理，而不只是替换远处家具。
- **适度灯光**：可改变冷暖、面积光方向/尺寸/强度，也可增添合理光源；避免极端曝光、遮黑或失真色彩掩盖问题。

保留父场景机械参数与任务逻辑。干扰物/背景可能改变接触、阻挡或支撑，因此每个新候选从其最终配置做原生复验；若需要重新调整机械参数或动作，登记新的机械候选/控制版本再验证，不悄悄改写父场景。纯视觉变更不使IK失效，可缓存运动参考；本流程仍保留每个候选的原生回归记录。

## 5. Blender / MuJoCo 资产一致性

两边保留完整显示网格、UV、纹理和主要背景，不默认抽稀、平均色替代或删背景。显示网格与必要碰撞体独立，但共享实例、局部坐标及变换；“完整显示”不等于将高面数渲染网格直接当正确的容器碰撞体。质量、惯量和接触结构按实际对象设置。

重点检查：

1. 导出完整物体变换，尤其非单位 scale；需要烘焙变换时处理法线、UV、材质槽和负尺度，不能只传位置/旋转。
2. Blender append/link 后，先完成场景链接并更新 dependency graph，再读取/复合 `matrix_world`。本次曾因更新顺序错误，使干扰物在两边尺寸和位置不同；用世界包围盒及代表帧投影核对，不能凭导入成功判定一致。
3. 杯子/设施几何变更时同步细节件、把手、装饰浮雕、铰链、显示和碰撞；包含检查用旋转后的容器局部坐标。
4. 保留纹理通道数据与色彩空间；按实际渲染器支持核对效果。PBR数据齐全不代表 MuJoCo 的阴影、高光和法线响应与 Blender 相同。

最终记录模型、控制、引用的网格/纹理哈希及相机/时间映射。请求视频时完整解码并抽查源帧身份；实际物理速度与事件对齐播放分开标注。输出 Blender RGB / MuJoCo RGB 对照；增强后没有对应真实拍摄，原 Real RGB 只能标为参考，不计为新场景同帧真值。逐项视觉复核和抽样复核的覆盖范围分别说明。

## 6. 控制速度与 tokens

- 先读计划、当前清单、参数差异和失败摘要；脚本执行采样/缩幅/统计，模型集中处理失败机制与少量视觉证据，不反复加载完整日志。
- 先数值验证，再为通过候选做按需关键帧/视频；失败候选保留数据，诊断渲染按需。不要为查一次缩幅是否有效重建基线或重新下载资产。
- 按模型、控制、资产、相机、输出设置建立依赖缓存；存在文件不等于缓存有效，修改实际依赖后才失效对应环节。
- 相同纹理共享引用，避免重复展开占满纹理缓冲；格式转换保留原图和来源，不以缩小分辨率冒充无损转换。MuJoCo版本不支持某格式时先转换为支持的无损格式。
- 完整背景渲染可试用静态缓存；先用代表帧测试CPU/GPU和内存，GPU不一定更快。避免多个大场景同时占满内存导致换页；保持质量和几何设置，调度变化单独记录。
- 本次场景专用的采样、IK和导出脚本不作为通用求解器发布。迁移到新任务时先核对模型命名、关节映射、事件与任务判据。
