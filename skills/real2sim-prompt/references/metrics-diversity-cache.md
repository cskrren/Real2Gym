# 物理指标、多样性与依赖缓存（v5.1）

第二步物理验收、第三步增强筛选或任意阶段恢复/复用产物时按需读取对应小节。这里定义执行接口与记录规范；现有场景脚本需要接入，不代表统一调度器或验收器已经实现。

## 1. 物理指标：单位、时间与接触语义分开

### 稳定性

先确定被评估对象、目标状态、参考坐标系、采样方式及本轮阈值。静止落定与随承载体稳定运动分开：后者使用相对承载体速度，并正确扣除承载体旋转造成的速度。

- 平移速度 `linear_speed_m_s = norm(v_xyz)`，角速度 `angular_speed_rad_s = norm(omega_xyz)`；通过仿真器明确的对象速度接口或已核对的状态映射取得，记录测量点和参考坐标系。
- 不直接对混合单位的六维速度求范数作为稳定性指标。明确 `linear_threshold_m_s`、`angular_threshold_rad_s`、`hold_duration_s`；阈值依对象、用途和采样精度预先登记，不将本次场景数值推广为固定默认。
- 在规定的末态验证窗口内，两项同时满足各自阈值，并连续维持至少 `hold_duration_s`；按实际模拟时间累计，中途超限重置持续时间，不用平均值或单个末帧代替。若要求结束时稳定，合格窗口必须延续到评估终点。
- 记录验证窗口、采样步长/最大间隔、两项峰值、末态持续合格时间和异常区间。采样间隙过大或时长不足标为未充分验证；不能将稀疏输出帧自动解释为全物理步连续稳定。
- 杯子落定、释放、容纳、门闭合和机器人平衡分别验收，静止不能替代任务成功。改变指标定义后从有完整时间/速度信息的原轨迹重评；证据不足才重跑，历史标签保留旧判据版本，不静默改判。

### 接触穿透

保留原始接触距离，统一以米记录、毫米展示。先核对仿真器距离和接触 margin 的定义，再计算几何穿透深度，不能把接触激活距离直接当穿透。

按对象对、任务阶段与持续时间分类：

| 类别 | 判断与记录 |
| --- | --- |
| 允许范围内的接触压入 | 预期支撑/抓持接触、深度满足预设容差，且未引发失稳或任务异常；保留非零深度，不称零穿模 |
| 待复核接触 | 短时尖峰、遮挡不明、显示/碰撞不一致或采样不足；检查局部窗口、力及几何，不能仅凭视觉判通过 |
| 任务阻塞穿入 | 超出本轮容差、持续穿墙/穿底、非预期自碰撞、通过穿透完成任务，或引发异常力/不稳定；停止接受该候选并修正 |

记录每类对象对的最大深度、最长连续超限时间、出现阶段、对应力/滑移和证据；显示网格穿入与物理碰撞结果分别报告。小于某个深度不自动豁免非预期危险接触；硬性阈值超限也不能用“任务完成”抵消。不得在看到失败后放宽阈值。

## 2. 增强去重与多样性

保留N每候选1–3项修改、允许单项、无类别覆盖配额。以下检查针对整个候选集合，不强制每个场景改变所有类别。

1. **精确去重**：用对象实例、基线、实际最终参数、目标硬件及相关资产版本构成规范化签名；键排序、单位与角度等价表示统一。初始抽样和缩幅后的参数分别保存，重复的最终机械配置只计一个N。重复结果可引用有效证据，不能重复充数。
2. **近似去重**：配置物理有意义的尺度，例如位置按对象尺寸/操作区尺度归一化，尺寸按相对变化，朝向按最短旋转角。资产类别/形状签名与连续参数分开比较；距离定义、各维权重与阈值记录在清单中，不直接混加米、角度和RGB值。缩幅后重新检查与原场景及其他候选的距离。
3. **视觉补充**：需要时用同一诊断相机下的轮廓、布局或图像特征辅助识别外观近重复；算法/阈值注明，不能只因光照不同就将相同机械配置计作新N。必要的接触关系差异也不能被整体画面相似度抹掉。
4. **处理**：近重复可保留为诊断/重复试验，但标记 `duplicate_of` 或 `near_duplicate_of`，不计入本轮要求的独立增强数量。变化缩小到不满足已设增强目标时换候选或报告不足，不无限逼近基线。
5. **统计**：同时输出尝试、失败、去重、保留数量；1/2/3项修改占比、各参数范围、归一化变化幅度、缩幅比例、背景ID/资产类别占比和父场景分布。筛选后的通过数不冒充无条件成功率。

采样模式可选 `random` 或 `balanced`。默认沿用用户选择；均衡模式可在集合层面对背景、资产或幅度分箱设置权重/配额，并记录不足与实际抽样概率。它不要求单候选覆盖全部类别，也不保证不可行类别必须产出成功样本。机械N与外观M分层去重；不同父场景复用同一背景不自动算重复，但必须展示背景覆盖统计。

## 3. 缓存依赖清单与恢复协议

每个产物使用统一清单记录依赖，不凭目录或完成标记存在就复用。可放在已有manifest中，无需为每个字段创建文件。

```json
{
  "schema_version": "1",
  "artifact_id": "candidate/render/view0/frame135",
  "kind": "render_frame",
  "producer": {"code_sha256": "...", "tool_version": "..."},
  "config_sha256": "...",
  "dependencies": [
    {"id": "native_trajectory", "sha256": "..."},
    {"id": "display_assets_manifest", "sha256": "..."},
    {"id": "camera_and_frame_mapping", "sha256": "..."}
  ],
  "status": "complete",
  "outputs": [{"path": "blender_rgb/0135.png", "sha256": "..."}],
  "validation": {"status": "pass", "validator_version": "...", "evidence_path": "..."}
}
```

上例仅为字段示意，省略号不可当真实哈希。图片、模型、纹理等引用依赖递归展开到真实文件哈希；配置包含随机种子、单位、对象/关节映射及影响输出的参数。检查项也作为有版本的产物，记录其阈值配置与输入证据。`validation.status` 字段本身不能证明校验实际执行。

| 变化来源 | 失效范围 | 通常可复用 |
| --- | --- | --- |
| 碰撞几何、物体尺寸、质量/摩擦、初态、机器人安装 | 相关动作适配、原生执行、物理验收及下游图像 | 原始输入、未变背景资产 |
| 控制或动作参考 | 原生轨迹与下游验收/渲染 | 已确认的静态资产 |
| 仅显示材质/纹理 | 两种RGB和视觉复核、视频 | 几何、FK、运动参考；第三步仍按约定对最终候选原生复验 |
| 相机、内参、帧映射 | 相关投影、RGB、视觉复核与视频 | 非视觉反馈控制下的原生轨迹；若相机参与控制输入则轨迹也失效 |
| 仅显示几何 | 图像与相关视觉/显示碰撞一致性检查 | 未受影响的物理轨迹；若用于控制或碰撞则追加相应失效 |
| 编码参数 | 视频与解码/帧身份检查 | 当前版本已完成的图像 |
| 验收阈值/检查器版本 | 相应验收记录与有效集合 | 原始轨迹与测量；证据足够时重评，无需重跑物理 |
| 新增背景碰撞体/干扰物 | 原生执行及下游结果 | 未变的源输入和资产 |

若原生模型文件包含材质引用，不能忽略文件变动后直接沿用旧模型身份；显式分离物理/显示依赖与本轮回归义务，最终验收仍绑定本次配置。清单的依赖来自实际实现，不只从参数名称猜测。

恢复步骤：

1. 比较当前生产程序、设置、直接与递归依赖哈希；缺失清单、未知依赖或不匹配标记 `stale/unknown`，不默认有效。旧产物可通过实际核验补录来源，不能补造成功记录。
2. 依赖一致后，检查输出存在、内容哈希和相应格式/帧身份验证；全部满足才记缓存命中，否则重建该产物及受影响下游。
3. 每帧独立登记相机、源/模拟索引、轨迹与渲染配置。中断后只补同版本缺失/损坏帧，禁止新旧版本混编。视频验证包含完整解码、数量、顺序、播放时间与代表帧身份。
4. 使用临时输出并在成功校验后原子提交完成清单；失败/中断保持 `partial/failed`。同一产物加任务锁，恢复时检查锁的所有者和存活状态，不无条件覆盖运行中的工作。
5. 将失败原因、缓存命中/失效原因、重算项和节省的调用/渲染量写入摘要；无实测时不虚报节省时间。不要为了重建一个产物删除有效的上游数据。

实现状态：这些是v5.1要求的统一接口与恢复协议。接入时必须让生产脚本实际读写清单、检查递归依赖并验证中断恢复；仅有文档、JSON模板或文件存在性判断，不标为“自动缓存已实现”。
