# 目标机器人选择与适配（v4）

仅 human-to-robot、换硬件或多硬件比较时读取。同硬件 robot data 沿用输入分支，不引入额外选型或人体重建。这里是执行流程支持，不是自动下载所有模型的安装器，也不是通用重定向求解器。

## 第一阶段：选择执行体

1. 用户已指定硬件则沿用，核实机械臂、末端、单/双臂、左右手和准确版本。未指定但已有接受配置则复用；否则先依据真实片段的接触类型、对象尺寸/重量、可达域和可用模型提出合适配置。本项目第一种配置固定为双 FR3 + Franka Hand 原装夹爪，简单抓放可从该配置起步；需要独立指尖/手内操作时考虑灵巧手。只有关键要求无法从输入确定时才询问，不把每次执行变成选型确认流程。
2. 在运行前明确资产实际名称与来源。ALOHA 是整套双臂系统，不是 FR3 的末端名称；本地若只有 ALOHA 2，应明确说明差别，用户指定的其他版本不能静默替换。通用、自定义或代理夹爪不得冒充厂商硬件。
3. 每个目标记录硬件名称、模型路径/来源/版本/哈希、臂与末端配置、基座/安装变换、TCP 和接触几何、关节/驱动限制、控制量含义、各臂角色、拟合或实测参数来源。可用 `target_robot` 与 `target_selection` 字段承载，无需重复维护多份契约。

| 配置 | 任务匹配与注意点 |
| --- | --- |
| 双 FR3 + Franka Hand（原装平行夹爪） | 第一种默认配置。使用厂商描述中的标准手掌、夹指、安装与开合关系；保持真实尺寸，核查开口、指长、可达性及柜体间隙。 |
| 双 FR3 + Wuji Hand | 当前第二项。使用 Wuji 官方左右手描述，记录准确型号和版本；逐指拟合接触与避碰，不复制 Allegro 的关节角、安装或控制参数。 |
| 双 FR3 + Sharpa Wave | 使用准确版本的左右手描述和完整关节/驱动映射；FR3 安装、逐指接触与任务执行独立验证，不能继承 Wuji/Allegro 结果。可视化触觉垫不等于已实现触觉传感仿真。 |
| ALOHA 系列 | 读取准确版本的双臂、耦合夹爪和完整驱动器配置；传动/滑轨位移不必等于半个夹持开口。 |
| 用户提供 URDF/MJCF + 末端 | 检查资产完整性、单位、限位、惯量、mimic/equality、驱动映射和安装关系，验证后接入相同流程；缺资产时明确缺项。 |

第一项模型来源：[Franka 官方 franka_description](https://github.com/frankarobotics/franka_description)，选择 `robot_type=fr3`、`ee_id=franka_hand`，固定实际使用的版本/commit。仅有无手 FR3 MJCF 不算资产完整。不得为通过任务加长夹指或用自制代理静默替代原装 Hand；先调整基座、抓姿和路径，仍不可行则记录硬件能力限制。

## 第一阶段：安装和首态检查

重建并保留已接受的操作物体、支撑物、核心背景和源相机。新目标机器人按任务布置基座与初态，不把人体骨长缩放为机器人尺寸，也不为可达性任意缩放物体。人体相机保持独立，不能因为替换机器人就绑到腕部。

导入完整关节链、visual/collision origin、左右手资产和安装件；包含驱动器的独立 XML/include 也要加载。确认控制器索引映射，不假定 qpos 与 actuator 一一同序。仿真转接件须记录实际变换、几何和不确定性，不能称为已验证的制造/装配模型。

检查基座、腕、指根、待机臂和安装件的自碰撞、臂间碰撞及桌面间隙。单手示范允许另一臂停在可达、无阻塞的待机姿态；不能随意 IK 到一个点后跳过全链碰撞检查。双臂模型加载成功不等于已验证双臂协作。

## 第二步第3–7环节：按硬件重定向与校准

- 从真实交互事件恢复对象相对的接近、夹持、搬运、落定与释放。源人体参考和目标机器人参考分开保存；目标记录必须包含实际使用的 TCP 偏置和重定向目标，而不是未修改的旧参考。
- 联合检查 TCP 位置、进场方向、夹持轴、关节限位与避碰。IK 收敛不证明图像对齐，位置误差很小也不能掩盖方向错误；按第4环节逐事件五问复核。
- **平行夹爪**：按实际碰撞面测量开口与闭合命令的关系，核实耦合/传动方向、接触高度和两侧承载。不能直接将人体指尖距离或另一夹爪命令赋给滑轨位移。
- **灵巧手**：用真实指垫面或碰撞胶囊的半径、轴向长度及方向确定接触，不把可视化 tip site 当作完整接触面。拟合抓持手指和其余手指的避让，检查不同高度接触、桌面干涉与物体转动。对捏可用拇指/食指，其余接触配置按任务决定，不能把一次对捏固化为所有任务默认。
- **接触控制**：依次修正安装/TCP、位置与角度、实际闭合、双侧或多指承载和滑移，再调整力/力矩、摩擦与软接触。有限接触面的扭转/滚动摩擦模型可按物理依据使用，记录参数来源；不能用无限摩擦或强控制掩盖几何错误。
- **释放**：真实落定事件与原生支撑接触共同用于校准开指时机和渐变，检查松开前后是否拖动、再抬起或抛出物体。不要无条件保持闭合直到片尾。源外追加动作单列时间映射，不能冒充真实事件。
- 最终控制增益、限力、重力补偿、摩擦和安装关系写入磁盘模型/配置。用最终模型和初态做独立完整回放，核对承载、落点、稳定性、穿入及实际轨迹；不依赖未保存的运行时参数。沿用已确定的用途容差，不为某候选事后放宽。

## 比较多个目标时的复用与失效范围

只跑用户指定的候选。共用真实视频、已接受静态场景、相机、实例与真实事件；为每套硬件保存独立模型、控制参考、原生轨迹、碰撞/任务记录和渲染，保留原基线。更换硬件使对应的安装、可达性、IK、开合、碰撞和动力学检查失效，不使无关静态背景或真实事件缓存失效。先检查短失败窗口和少量关键帧，合格后完整回归并一次输出视频，避免每次微调重渲染全片。

第8环节继续使用同一原生轨迹导出 Real RGB / Blender RGB / MuJoCo RGB，Real 保留人手、模拟显示所选机器人。逐配置分别报告物理、视觉、时序、协作与安装可信度；已接受的材质/背景可复用，但功能通过不改写成照片级还原。

## 经验适用范围

历史 stack_1081 的简单抓放已经在双 FR3 + 自定义平行夹爪、双 FR3 + Allegro V3、ALOHA 2 上分别完成过功能级原生执行。后两者仍是右臂操作、左臂待机；Allegro 有仿真安装与软接触残差，背景为接受的近似。该案例支持上述排查次序，不证明双臂协调、任意灵巧手动作或真实硬件可直接执行。案例中的位置增益、指间距、摩擦、3倍减速及2 mm接触容差不是新任务默认值；场景专用脚本不作为通用 skill 转换器分发。

配置更正：此前 stack_1081 和 drawer_1338 的平行夹爪结果使用自定义代理，不是 Franka Hand 的验证结果。切换到原装 Hand 后需重新执行安装、重定向、碰撞、原生任务和视觉检查，旧成功状态不能继承。

当前第二项按用户选择由 Allegro 改为 Wuji Hand。官方资产：https://github.com/wuji-technology/wuji-hand-description ，本地展示 commit `bbc2f64eec834aae616eacc2db1f69016f860c2d`。本次为 Wuji Hand，未声明 Wuji Hand 2。现有 FR3 组合仅完成静态模型展示，安装件、接触控制与任务执行仍需验证；历史 Allegro 成功不可归属于 Wuji。

Sharpa 当前展示资产为 MuJoCo Menagerie `sharpa_wave`（左右手），厂商名称 Sharpa Wave。当前仅静态结构展示，FR3 转接件是仿真假设，未验证实际安装或任务。


## 宇树人形与末端选项

按官方具体机型、版本和装配资产选择，不把各控制器可枚举的组合当作全部机械兼容。2026-09-11 核对：

| 机器人 | 当前主要选项 | 可选项 | 官方依据与限制 |
| --- | --- | --- | --- |
| G1 | Dex3-1 | Dex1-1、Dex2/5 | [官方遥操作仓库](https://github.com/unitreerobotics/xr_teleoperate)、官方 G1 URDF 的 Dex1-1 / Dex3-1 完整装配；[Dex2/5 产品页](https://www.unitree.com/Dex2-5/)明确适配 G1/R1。核对 EDU/旗舰版本与接口。 |
| H1-2 | `xr_teleoperate/assets/h1_2/h1_2.xml` 自带五指手 | Dex5-1 | [自带装配模型](https://github.com/unitreerobotics/xr_teleoperate/blob/main/assets/h1_2/h1_2.xml)；[H1/H1-2 官方参数表](https://www.unitree.com/cn/h1/)在 H1-2 栏注明可选 Dex5-1。自带手与 Dex5-1 是不同资产，不能互换名称。 |
| H1（4 自由度手臂） | 单独核对所选官方完整装配 | 不继承 H1-2 的兼容列表 | 官方参数表 H1 手部只写“选配”；没有具体组合证据时标未核实，不推断 Dex5-1、Dex1-1、Dex2/5 通用适配。 |

每轮仅执行用户选中的硬件，可选项不自动发起测试。完整官方 MJCF 优先保留其左右手安装变换、关节链、碰撞资产和力限制。独立手 URDF 的存在不证明已经取得对应机器人安装件；缺安装/CAD 时记录估计，不能宣称官方完整适配已经验证。Dex2/5 的联动与 Dex5-1 的被动关节按对应官方描述实现，不把全部可见关节当独立驱动器。对未来版本重新核对官方来源，不将本表当永久兼容保证。
