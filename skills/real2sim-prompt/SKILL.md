# Real2Sim Prompt v5

Real2Sim / Human2Robot 的基础重建分两步：**第一步，真实输入首帧 → 对齐的 Blender 静态场景；第二步，真实视频动作 → MuJoCo 实际物理执行 → 回传 Blender 多视角渲染。** 两步共用源索引、交互关键帧、坐标与参数来源记录。**第三步按需对已通过的场景做分层增强、动作适配与原生验证**；普通重建请求不自动扩展为增强批次。默认追求**可用的交互重建**；先让目标、相机方向、相对位置和操作过程可辨认，再按任务需要提高精度。用户认可的质量是当前项目的验收依据，不因仍有差异而无限返工。

## 两类真实输入，共用两步主流程

入口记录 `source_actor_type=robot|human` 与 `target_robot`，详见 [输入分支与动作重定向](references/input-and-retargeting.md)。支持单视角和多视角真实视频，不为缺失视角虚构 real RGB。

- **robot real data**：同硬件优先使用实测关节、TCP 与开合；RGB-only 用对应硬件关节链拟合。换硬件时显式执行 robot-to-robot 重定向。
- **human real data**：第一步选择/初始化目标机器人并对齐静态初态；**第二步第 3 环节**将手部与对象相对动作重定向成目标机器人的末端、关节和夹爪参考，再经第 4 环节复核和第 5–7 环节物理验证。

human 输入在第一步按用户选择确定机械臂与末端，未指定时采用已接受配置或说明选型依据。支持双 FR3 + Franka Hand（原装平行夹爪）、双 FR3 + Wuji Hand、双 FR3 + Sharpa Wave、ALOHA 系列、宇树 G1/H1-2 及用户提供的 URDF/MJCF；硬件名称不等于任务已验证。选型、换硬件和多候选比较时读[目标机械臂选择与适配](references/target-robot-selection.md)。

第二步固定使用同一编号，详见 [八环节执行说明](references/motion-execution.md)：

| 环节 | 主要工作 |
| --- | --- |
| 1 | 接收第一步场景及输入类型、目标机器人、坐标基准 |
| 2 | 从真实视频发现交互事件与关键帧 |
| 3 | 恢复运动参考；按输入分支进行状态复用或跨形态重定向 |
| 4 | 动作对齐、逐关键帧五问、问题邻域迭代 |
| 5 | 构建 MuJoCo 物理模型与核心背景显示 |
| 6 | 分阶段执行：对准、闭合、承载，再校准力与摩擦 |
| 7 | 最终模型完整回归，独立判定任务、接触、时序与视觉 |
| 8 | 原生轨迹回传 Blender，前后景材质/纹理/灯光优化，输出 Real/Blender/MuJoCo RGB |

## 先确定本轮范围与验收等级

先区分 `resume`、同输入的 `rebuild_scene` 与新输入的 `fresh_start`。`rebuild_scene` 从空白 Blender 建实体，不导入旧 blend；可按用户范围复用原始 Pi3/SAM 缓存与明确标注的数值初值，不声称盲测。清理仅删除用户指定场景的旧工程/备份，记录路径，保留原始输入和审计证据。续做时沿用已选版本、数据、接受范围和有效证据，只读最新清单与未关闭问题。用户要求从新视频开始时，建立只含真实输入与来源/时间说明的允许读取清单；不读取旧 Blender/MJCF、拟合参数、动作、参考关键帧或评测结论。通用技能和已核实的硬件描述可用，旧场景先验不能冒充新观测。保留审计记录在输入范围外；不能声称清空当前对话或把同一会话伪装成盲测。

基础重建包含静态初始化与动态执行两步；用户要求场景增强时再执行第三步。用户只要首帧时完成第一步；只要 Blender 动作预览时执行第二步的运动拟合部分，标明未做原生物理。输入已有接受的静态 `.blend` 时，从第二步的动作/状态准备开始；已有轨迹再直接做迁移，不能把静态工程误当成已有动作。只要求模型导入或诊断时在对应范围交付。第一步的画面认可不等于第二步的物理任务成功；用户要求走通实际物理执行时，不能停在模型加载或状态回放。

- **默认：可用重建**。主要物体、机器人连接与交互关系合理，视角和源帧对应正确，无影响任务的明显穿入、断裂或跳变。背景布局、非关键纹理、光照和细小轮廓偏差可带说明通过。
- **精确对齐**：用户要求定量几何、时序或接触精度时，按已约定指标评测任务区域。没有约定容差时，依据用途设定并记录，不把“任何非零误差”都当失败。
- **高保真/研究验证**：仅在明确需要时增加完整相机标注、精细外观、实测动力学辨识或连续检测等成本。可用重建不默认升级到此等级。

用户明确接受某版本时，记录场景哈希、接受范围、已知偏差与依据，停止追究已接受的非阻塞项。静态阶段用 `phase_acceptance.json` 绑定原话、候选与输入；用户接受非关键背景近似可以结束第一步，不能据此宣称动作、接触或动力学通过。保留历史测量，不能把用户接受改写为测量误差为零；单场景的容差不能推广为通用阈值。

### 人形机器人：保真优先与任务完成

人形目标执行前读[人形重定向、候选比较与验收](references/humanoid-retargeting.md)，硬件组合按[官方兼容与资产记录](references/target-robot-selection.md#宇树人形与末端选项)核实。**首先尝试复现 real 视频中的 action，保持原轨迹、原接触点和原位置，确保在避免危险及高难动作、避免不稳定接触动作的前提下完成任务。如果无法执行，再保持原执行逻辑、尽量保持原位置，并继续避免危险及高难动作、避免不稳定接触动作。** 优先减少非预期断触，检查接触建立、维持及撤离的稳定性；不以任务终态代替接触复核。

先尝试原站位＋原物体相对轨迹/接触。两者是同等重要的保真目标；未通过时，同一轮候选比较覆盖 **A：原位置＋新轨迹/接触** 与 **B：小幅新位置＋原轨迹/接触**，再按需要考虑两者均调整的 C。看完整动作连贯性、稳定性与任务结果选择；未跑分支写未验证，局部失败不证明整体不可行。固定骨盆成功只覆盖该仿真条件，不能证明自由站立或真机安全。

## 原轨迹与替代轨迹的验收标记

robot/human 换硬件时，允许在原示范无法完成后调整路径、接触方式或阶段时长完成同一任务。符合当前接受范围且通过完整原生回归的替代轨迹记为 `success_adapted_trajectory`，也算 Real2Sim 成功；与原轨迹的差异单列，不声称精确复现。保持硬件尺度、任务对象与原执行逻辑，保留原方案失败证据、候选实际改动、原因和源事件到模拟时间的映射。人形位置调整按上面的同等优先规则，用户明确固定站位时不得移动。

五问仍检查相机、场景、对象关系、接触和外观；已披露且符合授权的轨迹差异不重复作为阻塞项。视频明显区分“原生实际速度”与“事件对齐的替代轨迹”；不能用时间压缩掩盖停顿、重试或冲击。

## 五问是执行门槛

本节适用于建模/修改任务；只查看历史输出时如实审计，不要求重跑。开始执行读 [逐轮反馈与阶段门槛](references/execution-gates.md)，使用 `scripts/check_review_gate.py` 核验当前候选记录。它核验覆盖和证据关联，不能代替模型看图。

- **先复核，再分配修正轮次**：基线对真实事件代表关键帧生成全部视角图并逐帧回答五问；邻域仅在发现问题或调整时用于定位与回归。每次候选评测必须先更新受影响关键帧的五问及已触发问题的邻域检查，再决定接受、下一次修改或换阶段。完整五问不得推迟到最后补写。
- **对齐未通过，不转入完整物理执行**：源时间、相机和任务相关相对位置的 `fail / review / not_evaluated` 必须先解决。可做结构/FK/几何审计与短接触诊断来解释画面；不可用完整倾倒、摩擦搜索或更小步长绕过尚未完成的视觉对齐。
- **逐问题闭环**：每个阻塞问题保存源帧/视角、当前差异、预期关系、拟改参数和前后检查窗口；修正后关联同帧新图、五问及前后稳定边界，状态只能是 resolved / unresolved / regressed / accepted_by_user。修改了参数或优化器收敛不等于问题关闭。
- **优化目标与证据对应**：机器人到达估计目标的 IK 误差不等于对真实 RGB 的对齐误差。相机/基座/手眼/物体姿态需用同源多视角重投影、轮廓或可辨识关系复核，并留出未参与拟合的帧；不能只优化自建目标。
- **候选选择先看门槛**：先比较所需视角和事件的覆盖、相机/相对位置及几何，再比较任务和外观。不能以落碗数量或运行成功替代视觉门槛。“最佳失败候选”需声明仍未通过，禁止标为合格的第一步场景。
- **阶段实事求是**：视觉门槛仍失败时继续定位和修正；第二步写 not_started_alignment_gate，不为凑齐流程继续运行物理。用户另行要求诊断执行时可进行，单独标记，不能将诊断写成通过。

## 第一、二步持续修正闭环：不设次数上限

第一、二步当前不设修正次数上限（`max_iterations=null`）；第三步的批量采样与单候选缩幅预算另行配置，不要求每个增强候选都找到解。初始构建/基线检查记为第 0 轮，后续每次实际验证的不同候选继续累计计数；跨阶段、续做和上下文压缩不清零。计数用于审计和分析，不作为停止条件。

发现本轮验收范围内的阻塞问题，且存在可执行修正方案时，**必须继续修正，不能仅记录失败、导出好看的图或提出下一步建议就结束**。每轮按以下闭环执行：

1. **定位与假设**：选当前主要阻塞项，记录受影响对象/事件区间、当前指标和修改假设。优先检查相机与相对位置，再处理接触、稳定性及外观；已接受的非阻塞偏差不重新打开。
2. **修改与计数**：保存独立候选和输入差异，修改几何、初态、控制、参数或显示设置，开始验证时占用一轮。一个被实际验证的不同修正候选算一轮；多参数联合修改需说明耦合，批量/并行测试的不同候选分别计数，不能用一轮包装无限搜索。
3. **局部与前后检查**：先跑能检验假设的短段，向异常前后扩查至稳定边界。全步几何/接触扫描与所需视角五问增量更新；新增异常纳入问题表。局部失败保留证据，拒绝候选或在下一轮换方案。
4. **回归与选择**：候选局部通过后，完成受影响范围回归；准备判定成功时，必须从最终磁盘配置做完整相关回归，核对任务、几何/数值、源时间和所需视觉输出。复验同一未修改候选不额外占一轮；回归失败则本轮失败，继续定位并进入下一轮。不能以牺牲原已通过任务来换取单项指标变好。
5. **轮次结论**：记录修改前后指标、覆盖范围、剩余问题以及接受/拒绝理由；保留当前最佳可解释候选与失败基线。未改善时换假设，不重复同一修改凑满次数。

**停止规则**：全部本轮必需检查通过后结束。仍有可执行方案时继续修正，不因完成固定轮数而停止。只有用户停止/缩小范围，或存在缺失输入、环境不可用、无法在现有模型中检验的机制等具体阻塞，才可停止并明确未完成项；需说明已尝试什么、为何无法继续及缺少什么。单次失败、耗时较长或需要改变诊断方法不是提前停止理由。连续无改善时应更换诊断方法，不重复相同修改。

轮次随场景执行记录持久保存：续做、上下文压缩、切换阶段或换问题不重置计数；没有记录时从已有候选与日志恢复已用次数并注明不确定性。同配置的基础设施失败重试不是新修正轮，但须记录故障并排查，不能无限重试。纯检查或只导出已确认视频的任务不强制启动修正循环。

## 第一步：多视角首帧 → Blender 静态场景

### P0—P3：建立或恢复可检查场景

1. **数据、索引与事件发现**：确认全部视角、共同帧范围、坐标/单位、时间戳与可用机器人状态。保持源帧、Blender帧、视频帧映射，区分实测、拟合、插值和模拟；播放帧率不冒充采集速率。本轮仅首帧时只确认首帧索引及必要静态观测，不为静态建模遍历全视频；进入第二步再按[事件与复核规范](references/events-and-review.md)从真实视频建立关系变化时间线。用户明确暂不做时间同步时保留同帧假设，不另启动偏移估计，也不将假设称为硬件同步。
2. **几何初始化与多帧建模（robot/human 共用）**：单视角视频或单张 RGB 用 **MoGe-3** 初始化首帧几何；多相机首帧保留 **Pi3X 联合初始化**。保留可靠实测内外参，估计不覆盖测量。GPT6/SAM 识别交互物体、支撑和显著背景实例；**构建 mesh 以首帧 RGB 的轮廓、结构和遮挡为主，仅首帧参考点云辅助深度、平面、方向和尺度**，不直接把点云后处理当完整物体。选取后续视频中有新可见表面、遮挡解除或有效视差的重要稀疏 RGB 帧（首帧之外不超过10个时间索引；多视角按共享时间索引计数），结合相机/物体运动补全同一实例并重投影迭代。后续帧不生成或融合新的参考点云。单图不虚构后续观测。按[几何初始化](references/geometry-initialization.md)完成首帧及所用多帧复核后进入动作执行；机器人仍使用真实 URDF/XML 结构。
3. **机器人与相机**：使用当前硬件的URDF或等效结构，处理visual/collision的origin、axis、scale、limit及mimic。保留结构节点和安装件，检查FK与可见连接。固定相机使用共享外参；腕部相机通过机械链与固定手眼变换运动。以机器人运动、物体轮廓和多视角观测约束相机与物体，拟合及留出帧检查见[工程排查](references/engineering.md)。
4. **物体与场景**：先拟合操作区的尺度、形状、相对位置与材质；容器保留杯底、薄壁和空腔。显示资产与碰撞代理分开，共享对象局部坐标与运动。材质、纹理、光照和可见背景是最终视觉交付的一部分：先补对画面影响大的表面与轮廓，再按用途取舍小陈设；允许近似不等于交付基础色块。具体执行见[外观与物理轨迹渲染](references/rendering.md)。
第一步保留基础材质、纹理与灯光用于场景辨认和对齐；系统性的五项外观优化安排在第二步第 8 环节，按[外观优化顺序](references/rendering.md)在原生轨迹回传后完成。

5. **基线检查与冻结**：先检查完整实体结构、法线/闭合、空腔和支撑，再看同源全部视角的 ID/深度、灰模、RGB 并逐视角回答五问。碰撞审计包括隐藏桌腿、底座、工具和安装件，区分共面支撑与实体穿入；新视角/逐物体预览证明背面和支撑实际存在。保存接受的工程与清单哈希、已知偏差及下一步输入。已验证的资产与静态环境可复用；局部更新只使相关检查失效，不无条件重建基线。

实测关节与标定不得为视觉对齐被无记录改写。工具抓取偏差先查安装变换、URDF导入、工具尺度和物体姿态。碰到具体结构/接触问题时才读[工程排查与增量验证](references/engineering.md)。

## 第二步：动作恢复 → 原生物理 → Blender 对照

从第一步接受的静态场景开始，执行时先读[动作恢复与第二步衔接](references/motion-execution.md)。保持核心背景、可信相机、机器人尺寸和关节链；从真实视频恢复交互事件与运动参考，按 robot/human 输入分支复用或重定向为目标机器人的末端、关节与开合目标，再完成 MuJoCo 接触执行。只有动作或遮挡确实影响已接受背景时才重开对应局部检查。

### P4：交互关键帧与五问

执行本阶段先读[事件驱动关键帧、邻域五问与物理判定](references/events-and-review.md)。关键帧来自逻辑对象之间**接触、抓持、支撑、包含等关系的建立、解除或改变**。每个事件覆盖 `before / onset（或不确定区间）/ after`；起止、仓库参考、均匀采样帧只作额外上下文，不能替代事件覆盖。

真实与模拟事件分别记录，不强行配对不同时刻的首触。常规五问只覆盖真实事件代表关键帧；邻域作为问题定位与调整回归证据，首尾状态另列。每个关键帧、每个可用视角都回答：**① 最大差异；② 同帧相机对齐；③ 物体相对位置；④ 穿模与接触；⑤ 逼真度（材质、纹理、灯光、背景）**。先核对源时间/相机、相对位置，再修接触和外观。邻域记录受影响问题、证据与稳定边界，不逐帧强制重复完整五问；新增独立异常单列处理，遮挡未知不能自动通过。

首次逐帧建立观察；续做只更新受影响项，未失效的共享证据可以引用，未检查的新帧不能用邻帧结论代填。①是观察项；其余按当前验收等级使用 `pass / pass_with_notes / fail / review / not_evaluated`。用户接受的非阻塞偏差不反复否决。完整覆盖表与报告由结构化记录生成，避免重复撰写不变解释。

### 修改与回归：范围由影响决定

- 相机/源索引或重要相对位置有阻塞错误时优先修正，再处理接触和外观。针对本轮最大阻塞项修改，保留可回退版本；不顺手重做无关背景和动力学。
- 从出问题关键帧向前、向后检查，直到异常区间两端稳定。几何问题检查区间内全部输出帧，并在快速接触、薄壁和抓取/释放边界加密；不只修一张图，也不默认全片最细步长。
- 先让候选通过局部几何和过渡检查，再做受影响的物料模拟和最终渲染。保持四元数连续、接触约束及支撑；不要用逐帧大幅投影修正制造跳变。
- 依赖发生改变才重算：材质不使FK失效；局部杯轨迹不使静态柜体检查失效；相机变化重查相关全部投影；杯轨迹/几何变化使相关物料模拟失效。局部通过后对完整输出序列运行一次相关回归，已有缓存可复用。
- 同一种修正连续两轮没有改善时，换诊断方法或缩小自由度，并记录限制；不能仅因两轮未改善就提前交付失败。达到本轮等级且相关回归无新增阻塞问题即可停止；用户已接受的偏差不再循环修。

不能以隐藏对象、删除失败帧、独立平移视频或事后扩大容差制造通过。结果可以在既定容差内通过，不能宣称严格零相交或力学真实性已经证明。

### P5—P6：按需导出与验收

第二步第 8 环节默认交付同源、同视角的 Real RGB / Blender RGB / MuJoCo RGB 三方对照；Blender 使用完整显示场景，MuJoCo 使用对应原生轨迹及核心背景显示。第二步第 8 环节逐对象处理前景、支撑物与核心背景的材质/纹理；可用 Poly Haven 素材结合真实参考生成适配，按[前后景纹理闭环](references/rendering.md)记录覆盖、来源和多视角复核，不能只优化桌面。先按[外观与物理轨迹渲染](references/rendering.md)补材质、纹理、灯光与主要背景，再完成代表时刻的全部视角样帧检查。已有用户接受的外观直接复用；仅模型加载/接触诊断可用基础渲染，但必须标明用途。

用户只要关键帧时不渲染整段；请求视频时直接导出当前已确认版本，并披露保留偏差，不为次要外观重新打开整个建模任务。全部可用视角均交付，real/sim始终保持同源索引；不为两视角数据虚构第三视角。用户需要当前未解决版本的诊断视频时也可以导出，状态应写清楚。

冻结工程与渲染配置哈希，复用同版本帧并补齐缺帧。编码后完整解码核对数量、尺寸、播放时间，抽查首末帧及抓取/落料/释放事件与源图对应；视频成功和几何/时序精度分别记录。导出阶段不重跑未失效的建模和五问基线。

交付简要说明改了什么、通过哪一级、还有哪些不影响本次交付的差异，并给直接文件链接。只有记录结构需要创建/调整时读[输出约定](references/output-contract.md)。

### MuJoCo 迁移与实际物理执行

执行本步读[迁移与接触校准](references/mujoco.md)和[事件与物理判定](references/events-and-review.md)，沿用第一步工程与接受范围。流程是：固定输入与短性能检查 → 转移结构/空腔并核对同源状态 → 分阶段物理执行 → 对准、闭合、双侧承载、力与摩擦校准 → 最终完整回归 → 将本次原生轨迹回传 Blender 显示场景 → 按需精细渲染。

模型导入、运动学回放、基础接触、实际任务及几何验收分别记录。物体由驱动器、接触与重力推进；状态回放或抓持附着不能冒充原生任务成功。保持所有可用视角和源时间映射，五问仅增量更新受影响项。任务完成不覆盖未解决的穿入问题，第一步画面认可也不代表物理通过。

运行慢、物料/接触密集、需要恢复长跑或优化时，再读[性能与增量执行](references/mujoco-performance.md)。先短段定位成本和失败，候选有效后再跑全程；不要默认渲染每个失败候选或固定追加扰动批次。

多硬件接触适配、抓持后释放失败或穿入指标异常时，读[接触面、释放与交付排查](references/contact-and-delivery.md)。该参考适用于 robot/human 两类输入；保持当前两步八环节、首帧点云与稀疏 RGB 建模规则。

## 第三步：分层场景增强 → 动作适配 → 原生验证

用户要求增强已接受场景时，读[分层增强与缩幅重试](references/augmentation.md)。robot/human 输入均使用已选目标硬件，不因增强自动换机器人。

1. **单项探测**：交互物体与操作设施（例如杯子和微波炉）均可改变几何、位置、朝向；另测试桌面高度。得到有限测试下的采样范围，不能保证区间内或组合后均可行。
2. **机械候选 N**：随机选择 **1–3 项修改，包含单项**，不强求覆盖全部类别。失败后保留修改项，小幅缩减相对原值的偏差，重新适配动作、完整验证并保留失败原因；尺寸以1倍为基准，位移/角度以原始值为基准。可复用仍有效的成功候选，去除重复配置。
3. **外观候选 M**：对原场景及已通过的 N 个机械场景，各保留原外观，再随机加入前后景材质/纹理、真实干扰物、完整背景及适度灯光，形成 **(1+N)×(1+M)** 候选；实际通过数单独统计。每个新场景再做原生验证，失败场景不进入有效集合。
4. **支撑与交付**：桌面尺寸仅为合理承载按需调整，不独立随机化长宽/切角。桌面安装的机械臂随桌升降；地面安装的人形通常保持地面基准并重新检查可达性。Blender/MuJoCo 保留完整显示资产、纹理与一致变换，必要碰撞体另设。输出模型、参数差异、原生证据及所需对照；增强场景没有新配对 Real RGB，原视频只作任务参考。

第三步采用本轮配置的候选数、缩幅预算和结束条件；不要将第一、二步的持续修正要求解释为无限缩幅、无限采样或保证每个增强都成功。具体范围、验收、资产核对和性能经验以该参考为准。

## 控制时间与tokens

主入口只读一次；按需加载参考，优先读取摘要、问题区间和配置差异。数值扫描、候选搜索、统计、拼图、表格与视频核验交给可复用脚本；工具只返回计数、极值、失败区间和少量证据。模型集中处理新图像的空间歧义与方案选择。先看多视角总览，问题区域再放大；不要为每次微调重新加载全片图像和大段日志。

事件覆盖、五问证据和物理结果分别计数；未做的检查不能由参考图或退出码补成通过。第二步先做无渲染的数值诊断和少量分阶段候选，再渲染合格模型；只保存关键帧和异常窗口的详细接触量，全程扫描返回极值、区间和实际分母。参考脚本先检查适用性；不把场景专用导出器包装成未经验证的通用转换器。输出配置变化后更新相应哈希与依赖，保留失败基线供对照。
